# 订阅分组一次性迁移

在应用停写及验证备份后运行。新版需要先完成转换，旧程序不能再连接转换后的数据库。

- SQLite 通过 `SQLITE_PATH` 指定已存在的文件。
- MySQL、PostgreSQL 通过 `SQL_DSN` 连接。凭据放在受限环境配置中。
- 同一个命令用于本地、生产副本及经授权的正式切换。每个数据库分别核对实际目标。

```text
go run ./scripts/migrate-subscription-groups
go run ./scripts/migrate-subscription-groups -apply
go run ./scripts/migrate-subscription-groups
```

首尾两次检查只读。执行前启动旧程序的订阅生命周期处理，确认应生效/过期的组已处理，然后暂停所有旧写入。对照支付渠道逐单盘点旧待支付订单。已确认收款但尚未交付的旧单须保留原单号与可核实的条款并单独处理。无法确认条款的旧单再次回调时进入待核对。若仍有待支付旧单，完成逐单核对并记录归属后，带 `-pending-reviewed` 执行。

脚本保留订阅实例主键、起止、额度、已用、累计数，以及任务、预扣、支付和兑换历史的引用。它从当前模板给在用实例固化重置规则，保持已有重置时刻。脚本报告不明确的历史基础组并停止。先从旧库的审计、原始订阅快照查证并修正，再重读预检，不要将无法辨认的组替换为 `default`。

MySQL DDL 独立提交。迁移中断时保持停写，核实最近完成的步骤后重跑同一制品。尚无新版写入可在恢复演练通过的前提下恢复旧库和旧应用。新版业务写入以后优先前向修复，整库回退会覆盖窗口期间的订单与结算。
